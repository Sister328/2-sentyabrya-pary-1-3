# «Перекуп» — симулятор покупки и перепродажи автомобилей

**Учебный проект. Роль документации:** технический писатель и DevOps.

## Описание проекта
«Перекуп» — экономическая игра, в которой игрок покупает подержанные автомобили, договаривается с продавцами, ремонтирует машины, управляет деньгами и продаёт автомобили покупателям-ботам.

> Проект описан на этапе концепции. Технологии и функции, которые ещё не реализованы, обозначены как предлагаемые решения.

## Игровой цикл
1. Игрок изучает объявления на внутриигровом сайте.
2. В чате выбирает реплики для переговоров с продавцом.
3. Покупает автомобиль, при необходимости оформляет кредит.
4. На карте посещает гараж, магазин запчастей, СТО или банк.
5. Ремонтирует автомобиль самостоятельно с вероятностью успеха или заказывает ремонт на СТО.
6. Выставляет машину на продажу, общается с покупателями-ботами и принимает либо отклоняет предложения.
7. Получает деньги, рассчитывается с долгами и повторяет цикл.

## Локации
- **Карта** — переход между объектами.
- **Гараж** — хранение машин и самостоятельный ремонт; покупка гаража может быть отдельной игровой целью.
- **Магазин запчастей** — покупка деталей.
- **СТО** — профессиональный ремонт за деньги и игровое время.
- **Банк** — оформление и погашение кредита.
- **Сайт объявлений** — поиск автомобилей, переговоры и размещение собственных объявлений.

## Предлагаемые модули
- `GameController` — управляет игровыми сценариями.
- `Player` — деньги, инвентарь, автомобили и прогресс игрока.
- `Car` — характеристики, состояние узлов и оценочная стоимость.
- `MarketplaceService` — объявления, покупка и продажа.
- `DialogueEngine` — сценарии переговоров.
- `RepairService` — ремонт, стоимость, время и вероятность успеха.
- `BankService` — кредит и погашение долга.
- `SaveManager` — сохранение и загрузка прогресса.
- `UI` — карта, объявления, чат, гараж, магазин и банк.

## Предлагаемая архитектура и хранение
Для первой версии рекомендуется **модульный монолит**: одна программа, разделённая на модули. Для небольшого учебного проекта это проще в разработке и демонстрации, чем микросервисы.

На этапе прототипа сохранения можно хранить в JSON-файле. Если понадобится структурированная база данных, можно перейти на SQLite. Это проектное предложение, а не утверждение о существующей реализации.

## Запуск
Инструкция запуска должна соответствовать фактическому коду команды. Для Python-проекта после добавления `requirements.txt` и `main.py` пример команды может выглядеть так:

```bash
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

Если `main.py` и `requirements.txt` пока отсутствуют, запуск ещё не настроен.
